# DAY74 Local Customization Platform Doctrine

Timestamp: 2026-05-10 11:43:49

## Purpose

Make explicit the broader platform potential of the local user customization layer.

## Core insight

The local customization layer is not merely a convenience feature.

It is a platform architecture principle.

It allows JAA to be both:

- standardized enough to govern
- customizable enough to be personally usable

## Central / local architecture

### Central standard

The central standard provides:

- governed baseline
- shared doctrine
- common helper expectations
- standard operating vocabulary
- selected test-agent coordination
- reviewable promotion pathway

### Local customization

The local customization layer preserves:

- user-specific preferences
- local workflow adaptations
- pacing and command-style preferences
- privacy and distribution constraints
- local helper settings
- role-specific constraints
- durable user-specific operating adjustments

### Runtime playbook

The runtime playbook should combine:

- central standard
- local customization
- current day context
- active task context

## Test-agent implication

Each selected JAA test agent may eventually have:

- central JAA standard surface
- local customization file
- local receipts
- local helper preferences
- local privacy/distribution constraints
- local workflow adaptations

## Promotion pathway

Local customization is not deviation.

It is preserved adaptation.

Useful adaptations may later be reviewed for possible promotion into the central standard through a governed act.

## Governance boundaries

Local customizations do not silently mutate the central standard.

Central updates do not erase local customization.

Promotion from local customization to central standard requires separate review, selection, and ratification.

## Design consequence

The system should maintain local customization as a durable layer, not as a transient chat preference.

Central playbook updates should be applied in a way that preserves and reuses the local customization layer.

## Maxims

Central standards govern.

Local customizations persist.

Local customization is not deviation.

It is preserved adaptation.

Useful adaptations may be reviewed for promotion.
